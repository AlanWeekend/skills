# 中文注释审查

以实际实现为依据检查目标范围，默认交付问题清单。任务包含修正时，在同一范围内修正已确认的问题。

## 检查内容

| 层次 | 重点 |
| --- | --- |
| 文件用途 | 是否具体说明文件职责、入口及必要边界 |
| JS / TS 接口 | 参数、结果、异常、副作用与类型成员的语义 |
| Python Docstring | 模块、类和函数文档能否识别，各章节是否符合实际行为 |
| 内部流程 | 主要步骤、业务分支、异步处理和关键副作用是否解释清楚 |
| Vue 专项 | 组件输入输出、响应式、生命周期和模板业务区域的说明及合法位置 |
| 一致性 | 过期描述、虚构能力、重复说明及中文与标识符是否对应 |

## 审查与反馈

- 阅读本次 diff 和必要上下文，结合项目规范及维护范围检查。
- 优先处理与实现矛盾或会误导读者的说明，再报告关键缺失与表达问题。
- 每条问题附文件、行号、实际行为或缺口、阅读影响及具体建议；按真实影响确定优先级。
- 已有准确说明覆盖某项语义时视为满足要求；完整性以理解代码所需的信息衡量。
- 无法确认的业务约定列明依据缺口。反馈说明实际检查范围；没有问题时如实报告。
