# Python 中文文档字符串

让读者打开文件、查看类或悬停函数时，就能理解用途和调用约定。文档正文使用简体中文；工具标签、标识符和异常名称保持英文。独立可用，不要求安装其他 Skill。

## 覆盖与位置

- 每个涉及的自有 Python 文件有模块 Docstring，说明文件或包职责、主要入口和确实存在的关键依赖。
- 每个类说明职责、依赖和重要属性；构造器说明初始化行为，参数在类或构造器的一处完整说明即可。
- 每个自定义函数、方法、async 函数和业务相关的私有辅助函数都应有说明；短函数可以只有准确的一句，不强行填空章节。
- 模块 Docstring 在 shebang / 编码声明之后、future import 之前；类和函数的 Docstring 是各自正文的第一条语句。不要用上方普通 `#` 注释替代它。
- 对 property 描述这个属性表示的值、可空性及读取副作用；对生成器说明产出的每项，异步生成器同理；不为 lambda 插入会改变返回值的字符串。

## 文档格式

已有统一风格时保持一致；新项目默认 Google 风格。第一句用中文说明用途，再按真实接口选择章节：

| 标签 | 中文说明内容 |
| --- | --- |
| `Args:` | 参数的业务含义、单位、默认行为与约束，不把已有类型提示重复翻译一遍 |
| `Returns:` | 返回值的业务含义、空值或结果状态；不为只返回 None 的函数机械补“无返回值” |
| `Yields:` | 每次迭代产生的内容及停止条件，替代普通返回值说明 |
| `Raises:` | 与调用者相关、可确认的异常及触发条件，不推测整个调用链的所有异常 |
| `Attributes:` | 对调用方有意义的属性及语义；数据类、TypedDict 或模型字段也需要中文说明 |
| `Examples:` | 非直观接口的真实可验证用法，不编造依赖或执行结果 |

重要副作用、事务与资源所有权、并发、取消及幂等约定，用中文段落按真实实现补充。标准英文标签用于工具识别，标签下的内容保持中文。

## 内部代码与作用范围

- 文档字符串说明接口约定，函数体内使用 `#` 注释说明主要步骤、业务分支和难理解的语法，两者不能互相替代。
- 装饰器、上下文管理器、异步调用或 ORM 操作第一次出现且不直观时，解释它在当前代码中的作用；不把 Session 描述成自动提交的事务。
- 只补注释时不改签名、类型提示、装饰器、默认值、导入顺序或模型 Field 配置。保留许可证、工具指令和已有有效说明，排除生成与第三方代码。
- 框架可能把 Docstring 用于 OpenAPI 等对外文档；涉及此类入口时核对生成结果，不把内部敏感信息写进公开描述。

按需阅读 [references/examples.md](references/examples.md) 的模块、类、函数及生成器示例。

## 验证

- 使用项目已有解析、lint 或针对性测试；可以用 AST 检查模块、类和函数的 Docstring 是否能识别。
- 存在 doctest 或可运行示例时检查其正确性；只做语法验证时不能宣称示例运行成功。
- 核对注释与实现的异常、返回值和资源处理一致；检查不能证明业务准确性时明确限制。
