# 数据库命名与基础审计字段

以下是可跨项目复用的用户约定，适用于自有业务实体、关联、版本和日志表；存量兼容性及框架自行维护的结构按各自维护流程处理。

## 表与字段命名

- 表名采用小写 snake_case：`<business_domain>_<singular_entity>`，前缀使用实际业务域，后半部分使用单数实体或记录名。
- 复用项目领域词汇，同一业务域使用一致前缀和拼写；多词领域名同样使用 snake_case。
- 示例：`agent_definition`、`agent_version`、`workspace_member`、`knowledge_document`、`evaluation_case`、`agent_tool_binding`。
- 字段采用小写 snake_case，名称准确表达业务含义；缩写、关联列和单位后缀保持一致。
- 主键与关联列名称对应真实身份角色；索引、约束及序列名称沿用项目约定。

## 每张自有业务表的必备字段

所有新建的自有业务表均包含以下四个字段：

| 字段 | 语义 |
| --- | --- |
| `created_at` | 创建时间点，创建后保持不变 |
| `updated_at` | 最近一次持久化业务变更的时间点 |
| `created_by` | 创建记录的操作者稳定标识，创建后保持不变 |
| `updated_by` | 最近一次修改记录的操作者稳定标识 |

- 创建时同时写入两组值：初始更新时间等于创建时间，更新人等于创建人；后续更新维护更新组，保留创建组。
- 时间类型、时区基准和精度沿用项目约定，由可信统一机制生成；覆盖实际插入、更新、批处理、后台任务、原生 SQL 和导入路径。
- 操作者由可信身份上下文维护，类型与项目用户或服务主体的稳定标识一致，关联约束按实际模型确定。
- 系统、匿名或历史导入场景使用明确的系统主体，或按约定允许空值并说明原因与范围；身份与时间的历史回填依据真实来源。
- 新建正常业务记录具备真实创建和更新时间；历史未知时间按项目的未知值策略处理。

## 存量变更与检查

- 对存量差异，在任务范围内规划兼容迁移，核对回填来源、外键、查询、接口与调用方；已有数据满足条件后再收紧约束。
- 为四个审计字段维护准确业务说明，核对模型、迁移和实际 SQL 的名称与语义一致。
- 验证涉及的插入、更新、批处理及升级路径，确认每张新表字段齐全、各写入路径维护语义；说明实际验证范围。
