# 中文逻辑与流程注释

让中文读者看懂“当前步骤做什么、为什么需要、如何衔接下一步”。说明文字使用简体中文，标识符和必要术语保留英文。不绑定语言或框架，也不要求安装其他 Skill。

## 覆盖要求

- 每个函数体说明主要处理步骤；短函数可以由紧邻函数说明覆盖，避免在直接返回语句旁重复相同文字。
- 对具有业务含义的条件分支、循环、异常处理、转换、异步等待及副作用块，说明触发条件、处理对象和目的；共享意图的相邻语句可共用一段注释。
- 对难以直接理解的解构、闭包、生成器、装饰器、泛型、响应式或上下文管理语法，说明它在当前代码中的实际效果，不展开无关语法教程。
- 外部读写、权限与归属、事务边界、并发、取消、重试和资源释放，按实际实现说明影响范围及失败处理。没有对应实现时不能编造保证。
- 对重要业务变量、状态、配置值说明含义、单位、允许范围或状态转换；不为每个导入、括号和显然赋值添加重复解释。

## 写法与边界

1. 先读调用上下文与实现，明确数据来源、输出和副作用；不确定的业务原因先查证，不以猜测写成事实。
2. 在对应逻辑块之前写说明；只有单行局部信息使用尾注，避免长中文尾注挤坏排版。
3. 注释用“校验会话归属，避免读取其他用户的消息”这样的业务表达。确实需要解释复杂语法时，同时交代语法的效果。
4. 修改实现时同步修正失效注释；补注释时检查同一文件的相关流程，但不扩大到无关模块或重构。
5. 只补注释的任务保持行为、导入顺序、类型、签名和外部调用不变。保留许可证、工具指令和已有有用说明，排除生成与第三方代码。

需要校准细节密度或处理异步、错误分支时，阅读 [references/examples.md](references/examples.md)。

## 验证与交付

- 用项目已有语法、格式、类型或针对性测试验证受影响文件；注释不得破坏字符串、模板、指令或表达式。
- 检查是否遗漏重要步骤、注释是否与实现一致，以及是否把不存在的业务保障写成事实。
- 汇报涉及文件和实际验证；不能运行的检查说明原因，不承诺注释覆盖率或运行效果。
