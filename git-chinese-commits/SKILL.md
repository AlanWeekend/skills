# 中文规范 Git 提交

任务包含提交信息、创建提交或推送时使用，按用户实际授权执行对应操作。

## 提交信息

- 格式为 `<type>(<scope>): <中文描述>`，scope 可省略。破坏性变更按仓库约定使用 `!` 或 `BREAKING CHANGE:`，中文解释影响及迁移要求。
- 默认 type：`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert`；scope 沿用项目命名。
- 标题描述与正文使用简体中文，类型、范围、标识符、命令和工具标签保持英文；按真实变更编写，正文按需说明原因、影响及验证限制。
- 使用仓库现有 commitlint 配置及命令；无配置时在临时 CLI 环境使用 `@commitlint/config-conventional` 校验。

## 暂存与提交

1. 核对代理规则、当前分支、Git 状态、提交配置和本次授权范围。
2. 区分任务改动与原有工作区、暂存区内容，保留无关改动；只暂存确认的文件或补丁。
3. 按变更运行针对性验证，检查完整暂存差异与空白问题，校验拟提交信息。保留 hooks 和签名要求，检查失败时处理原因。
4. 紧邻提交前重新核对 HEAD、暂存范围及暂存树或等效摘要；并发变化后重新审查。
5. 通过可靠参数或 UTF-8 文件传入中文信息，提交后核对实际提交 ID、标题、文件范围和剩余状态。

## 推送

- 用户授权推送时执行；只要求提交时交付本地提交。
- 核对 remote、分支及远程变化，使用普通快进推送。远程更新时保留本地和用户改动，按仓库允许的方式整合；无法安全整合时报告具体冲突。
- 历史改写、强制推送与更换远程地址需要单独明确授权。
- 推送后确认目标分支包含预期提交；交付提交 ID、中文标题、验证结果、推送状态及剩余改动。

类型、临时校验和中文编码示例见 [references/examples.md](references/examples.md)。
