# JS/TS/Vue 中文注释

## 核心要求

编写或修改 JS、TS、JSX、TSX 及 Vue SFC 时，检查整个涉及文件并补齐以下中文注释：

| 层级 | 覆盖对象 | 注释内容 |
| --- | --- | --- |
| 文件 | 每个被创建或修改的文件 | 文件职责、所属模块和关键依赖 |
| 函数 | 函数、方法、构造器、箭头函数和匿名回调 | 用途，以及存在时的参数、返回值、异常和副作用 |
| 类型 | 类、接口、类型别名、枚举和复杂泛型 | 语义、约束和使用边界 |
| 逻辑块 | 条件分支、`switch/case`、循环、异常处理、异步流程、数据转换和副作用操作 | 逻辑意图、业务原因或必须保持的条件 |
| 模板区块 | Vue `<template>` 中独立的筛选、表单、工具栏、列表、表格、分页、详情、弹窗、抽屉和状态反馈区域 | 区块的业务目的、数据范围或交互边界 |
| 模板分支 | 业务含义不直观的 `v-if/v-else`、`v-for`、权限控制、动态组件和具名插槽 | 分支对应的业务状态、循环对象或插槽职责 |

每个函数和逻辑块都必须有注释，即使实现很短；此时用一句简短中文说明职责或意图。
模板注释按语义结构添加，不要求逐标签注释。包含多个独立业务区域的模板必须标注主要区块；简单展示组件不为满足数量要求添加无意义注释。

## 注释位置

- 普通 JS/TS 文件把文件说明放在 shebang、许可证或必须置顶的指令之后。
- Vue 单文件组件把文件说明放在 `<script>` 或 `<script setup>` 块开头，不改变 SFC 区块顺序。
- 函数和类型使用紧邻声明的 `/** ... */` 注释。
- 逻辑块使用紧邻控制语句或分支的 `// ...` 注释。
- Vue 模板使用 `<!-- ... -->`，放在对应完整区块或条件链之前，不插入文本节点内容中。
- 不在 `v-if` 与 `v-else-if/v-else` 节点之间插入注释；需要说明时，在整条条件链之前统一解释。

## 编写原则

- 注释使用中文；标识符、协议名和必要技术术语可以保留英文。
- 注释说明职责、意图和约束，不逐行翻译导入、赋值、调用或直接返回。
- 模板注释说明业务区域和状态含义，不复述标签名、组件名、样式、布局方向或可直接读出的显示文案。
- 避免在第三方组件插槽、`Transition/TransitionGroup`、SSR hydration 边界或依赖直接子节点结构的位置随意插入注释；应将注释放到不会改变插槽内容和渲染结构的外层语义边界。
- 修改代码时同步修正失效注释，并补齐当前文件缺失的脚本层级和必要模板语义注释。
- 只补充注释和完成用户要求的代码，不借机修改无关业务逻辑。
- 跳过生成代码、压缩文件和第三方源码，并在结果中说明跳过原因。

## 工作流程

1. 识别任务涉及的 JS、TS 和 Vue SFC，排除明确的生成或第三方代码。
2. 理解文件职责、代码流、模板区域和 UI 状态后再修改代码。
3. 按文件、函数、类型和逻辑块补齐脚本注释，并按业务区块和复杂分支补齐模板注释。
4. 运行项目现有的格式化、类型检查、测试或构建命令。
5. 按检查表复核后再报告完成。

## 交付检查

- [ ] 每个涉及文件都有中文文件说明。
- [ ] 每个函数、方法、构造器、箭头函数和匿名回调都有中文说明。
- [ ] 每个类、接口、类型别名、枚举和复杂泛型都有中文说明。
- [ ] 每个条件分支、循环、异常处理、异步流程、数据转换和副作用块都有中文说明。
- [ ] 多区域 Vue 模板的主要业务区块具有中文结构注释。
- [ ] 复杂模板分支、循环、权限控制和插槽的业务含义能够从注释或代码本身明确判断。
- [ ] 模板注释没有破坏条件指令相邻关系、插槽内容或运行时 DOM 结构。
- [ ] 注释准确且没有逐行复述代码。
- [ ] 跳过项和无法运行的验证已明确说明。
