# 中文文件用途说明

让读者打开文件后先知道它负责什么、如何被使用。每个涉及的自有源码文件都应有用途说明；已有准确说明时维护它，不新增重复文件头。此 Skill 可独立使用。

## 应说明的内容

- 第一段直接写具体业务用途，区分页面、可复用组件、业务服务、基础设施和入口。
- 按文件实际复杂度补充主要职责、调用入口、关键依赖、输入输出或重要使用边界。简单工具文件一句话即可，不机械填满模板。
- 页面和组件写清它服务的交互、数据来源及与父组件或路由的关系；服务写清它处理的用例和调用方。
- 只陈述可从代码与项目约定确认的事实，不编造作者、日期、负责人、权限保障或调用关系。

## 放置位置

| 文件类型 | 方式与位置 |
| --- | --- |
| Vue SFC | 默认在文件开头使用顶层 `<!-- ... -->`；保留许可证等必须置顶内容。如果已有统一的 script 文件头格式则维护它，不重复，也不为注释调整 SFC 区块顺序 |
| JS / TS / JSX / TSX | 使用 `/** ... */` 模块说明；shebang、许可证、三斜线引用及必须置顶的指令按原要求保留位置 |
| Python | 模块 Docstring：在 shebang / 编码声明之后、普通 import 及 `from __future__` 之前，成为模块第一条语句；不把普通字符串放在 import 后冒充模块文档 |
| 其他语言 | 使用语言合法的文件或模块文档注释，并遵循编译器对 package、crate、预处理指令等位置的要求 |
| JSON、生成代码、第三方源码 | 不强行加入注释；需要时在相邻维护文档中解释，并说明排除项 |

许可证、来源声明和编译工具指令与业务用途说明可以并存，不能互相覆盖。对空的 Python `__init__.py`，有实际包职责时用简短包说明，不编造导出接口。

按文件类型查看 [references/examples.md](references/examples.md) 的合法位置示例。

## 验证

- 确认每个目标文件有准确的中文用途说明，且未重复声明或与实现脱节。
- 确认 Python 的 `__doc__` 仍能识别模块说明，Vue 和语言特定指令的结构不被改变。
- 运行项目现有的适用解析、格式或针对性检查。补充文档不等于实现了文档中描述的业务功能。
