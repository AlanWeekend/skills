# 业务对象身份设计

让同一对象在改名、配置修改、版本发布和数据流转中保持稳定、可解释的身份。

## 确认身份角色

读取相关模型、约束、创建逻辑、API 和迁移约定，区分实体、草稿、版本、快照、关联与事件。

| 角色 | 需要明确的内容 |
| --- | --- |
| 记录键 | 唯一定位当前记录的单列或复合主键 |
| 业务对象 ID | 跨草稿、版本或快照识别同一个持续存在的对象 |
| 外部标识 | 外部系统或公共接口使用的标识及本地映射 |
| 业务编码 | 确有业务需要的可读编码、唯一范围与变更规则 |

同一字段可以兼任兼容角色，实体主键可以直接承担稳定对象 ID；按对象实际需要配置字段，关联表可以使用复合键。

## 设计要点

- 明确对象 ID 的分配时机、所有者、生成来源与唯一范围；改名、配置修改和新版本默认保留对象身份。
- 版本或快照有独立记录键时，通过稳定对象 ID 关联原对象；版本号、对象 ID 和请求幂等键分别表达各自语义。
- 兼容现有自然键、代理键和外部契约；对名称、邮箱等可变属性，评估变更、回收与引用代价。
- 按数据库、部署拓扑、写入方式和公共接口需求选择序列、UUID、有序标识或统一分配器；记录生成器的协调范围、节点和时钟假设。
- 在约定范围内建立数据库主键或唯一约束，引用关系保留租户或组织边界，按真实模型确定外键。
- 业务编码按需定义大小写、唯一范围、别名、变更与复用策略。
- API、消息和客户端往返无损保留标识，特别核对大整数经过 JSON 和 JavaScript 的精度。

复制、发布、合并和跨环境导入的身份处理见 [references/identity-lifecycle.md](references/identity-lifecycle.md)。

## 验证与交付

记录本次涉及对象的记录键、对象 ID、唯一范围、生成来源和引用方式。按改动验证改名与发布保留对象身份、复制分配新身份、迁移保留身份或完成映射，以及唯一约束、引用完整性和接口往返精度；列明尚未验证的生成器假设。
