# Vue 页面与组件中文注释

让读者先理解组件的用途，再理解数据如何流动、交互如何触发以及状态如何展示。可独立使用，不绑定 UI 库、路由器、状态库或请求库。

## 每个 SFC 都要有用途说明

- 文件开头用顶层 `<!-- ... -->` 写明是哪个页面或组件、主要职责、数据来源及重要交互边界；保留许可证和已有必须置顶的内容。
- 已有统一的 script 文件头时维护它，不重复写两套；不为注释迁移 `template` / `script` / `style` 的位置。
- 简单组件一两句即可；复杂页面说明和父组件、路由或 Store 的实际关系，不编造 API、权限或状态管理机制。

## 脚本层需要说明什么

- Props：用途、默认值、可选 / 空值语义、只读约定；Emits：触发时机和载荷；Slots / v-model：使用方提供或接收的内容与同步约定。
- 每个业务函数、方法及回调说明用途；存在参数、返回值、异常或副作用时，用中文 JSDoc 写明。短回调可由紧邻的整体调用说明覆盖。
- `ref` / `reactive` 状态写清业务含义；`computed` 写清派生依据；`watch` / `watchEffect` 写清触发来源、执行时机和副作用。
- 数据加载、提交、防抖、响应乱序、取消、异常反馈、订阅及卸载清理，按实际实现说明步骤与边界。没有清理逻辑时不能用注释宣称已释放资源。
- 前端权限和筛选只是展示行为；没有服务端实现证据时，不写成跨用户安全保证。
- 保持原有 Composition API / Options API，不因为补注释转换 API 风格或改变运行行为。

## 模板和样式

- 筛选、表单、列表、详情、弹窗、状态提示等主要业务区块前使用 HTML 注释说明目的；不要逐个解释展示标签和样式类。
- 复杂条件链、循环和插槽说明对应业务状态、循环对象和交互职责。
- 不在 `v-if` / `v-else-if` / `v-else` 链之间插注释；说明放在整个条件链之前。
- 不把注释插进属性值、文本插值或依赖直接子节点结构的插槽 / Transition 边界。必要时放在外层或 script 中，保持条件链与节点结构。
- 样式只解释非直观布局约束、覆盖第三方样式的原因或浏览器兼容处理，不重复翻译 CSS 属性。

按需阅读 [references/examples.md](references/examples.md) 的完整组件示例。

## 验证

- 检查文件头、组件契约、状态流、业务函数和主要模板区域是否齐全且相互一致。
- 使用项目现有 Vue 解析、格式、类型或针对性检查；涉及关键 UI 时按项目现有方式检查渲染。
- 说明实际检查与排除项；注释本身不能替代功能或可访问性验证。
